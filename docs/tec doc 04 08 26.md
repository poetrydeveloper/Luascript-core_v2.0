Luascript Core 2.0
==================

PURPOSE
-------
luaScript является промежуточным языком между намерением пользователя
и детерминированным Luau-кодом для Roblox.

Главная архитектурная идея:

AI != compiler

AI proposes changes.
Compiler validates and deterministically builds the project.

--------------------------------------------------
1. AST
--------------------------------------------------

AST является каноническим структурным представлением luaScript.

AST имеет:

- deterministic serialization
- SHA-256 hash
- clone
- equality

AST hash используется как fingerprint payload.

--------------------------------------------------
2. SHELL
--------------------------------------------------

Shell является версионной единицей проекта.

Shell содержит:

identity:
    id
    hash
    version

position:
    path
    parent
    order

lifecycle:
    actual
    generation
    createdAt
    supersedes

semantic:
    name
    purpose
    tags
    description

payload:
    AST

Shell отвечает одновременно за:

- кодовую принадлежность
- семантическую принадлежность
- позицию в проекте
- версию
- историю эволюции

--------------------------------------------------
3. SHELL REPOSITORY
--------------------------------------------------

Repository хранит историю Shell.

Для одного id:

v1 -> v2 -> v3 -> ...

Каждая новая версия:

- получает новый hash
- получает новый version
- получает новый generation
- указывает supersedes на предыдущий hash
- становится actual
- предыдущая actual становится inactive

Старые версии не уничтожаются при обычной эволюции.

--------------------------------------------------
4. PROJECT TREE
--------------------------------------------------

ProjectTree представляет структуру проекта.

Например:

systems
└── weapon
    ├── timer
    ├── combat
    └── inventory

Tree отвечает за:

- path
- parent
- order
- hierarchy

Tree содержит Shell, являющиеся текущим состоянием
структуры.

--------------------------------------------------
5. PROJECT SNAPSHOT
--------------------------------------------------

Snapshot является компактным fingerprint структуры проекта.

Он содержит только:

path
parent
order
shellId
version
hash

Snapshot НЕ содержит полный AST.

Snapshot hash идентифицирует конкретную конфигурацию проекта.

--------------------------------------------------
6. PROJECT STATE
--------------------------------------------------

ProjectState фиксирует конкретное состояние проекта.

ProjectState содержит:

snapshotHash
nodes[]

Каждый node ссылается на:

shellId
version
hash
path

Таким образом ProjectState является воспроизводимой ссылкой
на конкретную версию проекта.

--------------------------------------------------
7. PROJECT RESOLVER
--------------------------------------------------

Resolver превращает:

ProjectState

в:

ResolvedProject

Он проверяет:

- Shell существует
- version существует
- hash совпадает
- path совпадает

Таким образом поврежденное или подмененное состояние
не может незаметно попасть дальше.

--------------------------------------------------
8. PROJECT CONTEXT
--------------------------------------------------

ProjectContext является представлением проекта для AI.

Он НЕ обязан содержать весь AST.

Контекст должен быть многоуровневым.

LEVEL 0:
    topology

LEVEL 1:
    topology + semantic metadata

LEVEL 2:
    selected Shell + metadata + AST summary

LEVEL 3:
    selected Shell + full AST

AI получает минимальный необходимый контекст.

--------------------------------------------------
9. AI CHANGE
--------------------------------------------------

AI не изменяет ProjectTree напрямую.

AI формирует proposal.

Например:

"Добавить pistol weapon system"

Proposal содержит:

- target path
- operation
- semantic intent
- source Shell/version
- proposed AST change

--------------------------------------------------
10. VALIDATION
--------------------------------------------------

Proposal проходит validation.

Проверяются:

- schema
- AST validity
- language rules
- semantic constraints
- project constraints
- references
- duplicate paths
- incompatible changes

Invalid proposal НЕ попадает в Repository.

--------------------------------------------------
11. EVOLUTION
--------------------------------------------------

После успешной validation:

old Shell:

    actual = true
    version = N

становится:

    actual = false

и создаётся:

    version = N + 1
    generation = N + 1
    actual = true
    supersedes = old.hash

Старая версия остаётся доступной.

--------------------------------------------------
12. ROLLBACK
--------------------------------------------------

Rollback не уничтожает историю.

Repository может сделать:

activate(id, version)

После этого указанная версия становится actual.

Таким образом:

v1 -> v2 -> v3

может стать:

v1(actual)
v2
v3

--------------------------------------------------
13. WEAVER
--------------------------------------------------

Weaver получает ResolvedProject.

Weaver НЕ принимает архитектурных решений.

Он:

1. читает Shell
2. читает AST
3. применяет deterministic code generation
4. собирает итоговый Luau

Основное свойство:

    same ProjectState
        +
    same compiler version
        =
    same output

AI не участвует в Weaver.

--------------------------------------------------
14. REFACTORING
--------------------------------------------------

Refactoring выполняется как эволюция Shell.

AI может предложить:

old structure:

systems.weapon.timer

new structure:

systems.weapon.cooldown.timer

Validator проверяет proposal.

Repository создаёт новые версии.

ProjectTree получает новое актуальное состояние.

Старое состояние остаётся восстановимым.

--------------------------------------------------
15. MEMGRAPH
--------------------------------------------------

Memgraph является внешним/визуальным представлением
эволюции проекта.

Локальная истина:

    ShellRepository
    ProjectTree
    ProjectState
    AST

Memgraph:

    visualization
    navigation
    history
    dependency graph
    semantic graph
    backup/index layer

Memgraph НЕ должен быть единственным источником истины.

--------------------------------------------------
16. GARBAGE COLLECTION
--------------------------------------------------

Старые Shell могут сохраняться достаточно долго для rollback.

В будущем вводится GC policy.

Например:

keep:
    actual versions
    последние N поколений
    versions referenced by snapshots
    versions referenced by releases
    versions referenced by Memgraph
    explicitly protected versions

collect:
    unreachable
    unprotected
    старше retention window

Важно:

GC не является частью обычной эволюции.

Он является отдельным maintenance process.

--------------------------------------------------
17. CORE PRINCIPLE
--------------------------------------------------

AI может быть слабым.

Compiler должен быть сильным.

AI:

    understands intent
    proposes structure
    proposes AST modifications

Compiler:

    validates
    versions
    resolves
    builds
    reproduces

Therefore:

    intelligence is probabilistic
    project state is deterministic
    build is deterministic

--------------------------------------------------
18. TARGET PIPELINE
--------------------------------------------------

User:

    "Добавь игроку пистолет."

        ↓

AI получает ProjectContext

        ↓

AI определяет необходимые Shell

        ↓

AI запрашивает дополнительные ветки

        ↓

AI формирует proposal

        ↓

Validator

        ↓

ShellRepository.save()

        ↓

ProjectTree

        ↓

ProjectSnapshot

        ↓

ProjectState

        ↓

ProjectResolver

        ↓

Weaver

        ↓

Luau

        ↓

Roblox
